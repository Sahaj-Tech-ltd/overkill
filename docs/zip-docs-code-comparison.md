## Highest priority gaps

1. **The compliance proof layer is incomplete.** Tool receipts are appended in both Run and Stream, but `ReceiptChain` stores a process-local slice. `VerifyChain` checks internal hashes, links and sequence; it has no signature, trusted external head, expected length or durable chain store. There is no identified `overkill audit export` / standalone `overkill verify` implementation. A safe function-only probe confirms that a valid chain with its final receipt removed still verifies. This does not contradict detection of an altered middle entry: it exposes the missing external anchor. “Every action cryptographically proved” and “signed correction mutations” are unsupported. [Receipt implementation](/Users/abc/Documents/overkill/internal/agent/receipts.go:53), [Run dispatch](/Users/abc/Documents/overkill/internal/agent/react.go:216), [Stream dispatch](/Users/abc/Documents/overkill/internal/agent/stream.go:637), [probe](/Users/abc/Documents/overkill/.cache/zip-review-receipts-probe.json). The existing completion auditor checks work claims; it is a different feature from a signed receipt export.

2. **Cloud-first is a proposal, not the current architecture.** The current memory/correction stores and local authenticated API do not establish tenant-scoped storage, organization membership, seat/role authorization, an organization receipt chain, billing or a cloud control plane. Repository searches did not identify those surfaces. A project/session ID or scoped peer credential is not an organization security boundary. [Memory store](/Users/abc/Documents/overkill/internal/memory/postgres.go:89), [corrections schema](/Users/abc/Documents/overkill/internal/learning/store.go:47). Tenant isolation must cover queries, writes, caches, vector schemas, tools and exported artifacts before a shared deployment can be treated as multi-tenant.

3. **Several advertised memory features are not the active execution path.** Seahorse has a DAG implementation and unit tests, but no production importer was found; the CLI installs the LCM-backed compactor. The evolution daemon constructs an engine with a nil draft generator and runs it with apply mode false; no production `Engine.RecordTurn` caller was found. This does not deliver automatic turn-to-skill evolution. Correction retrieval is bounded PostgreSQL keyword matching, not the advertised TF-cosine correction graph; old corrections can be evicted. [Active compactor](/Users/abc/Documents/overkill/cmd/overkill/run.go:457), [Seahorse](/Users/abc/Documents/overkill/internal/compaction/seahorse/seahorse.go:1), [engine construction](/Users/abc/Documents/overkill/cmd/overkill/daemon.go:415), [nil generator exit](/Users/abc/Documents/overkill/internal/learning/evolution.go:282), [retrieval](/Users/abc/Documents/overkill/internal/learning/store.go:139). Persistence and prompt injection of relevant corrections exist; “correct once, never repeat” is not a guarantee the code can provide.

4. **Automatic protection/resume hooks still lack production wiring.** `SetCheckpointSnapshotter`, `SetCheckpointManager` and `SetFlowStore` have tests but no production setter calls were found. The daemon does create a real PostgreSQL flow store and expose flow RPCs, so deleting that store would be a regression. The missing part is automatic agent timeout → saved flow → scheduled resume, plus automatic pre-mutation snapshots. Manual checkpoint tools and daemon flow operations do not prove these automatic paths. [Checkpoint hook](/Users/abc/Documents/overkill/internal/agent/checkpoint_guard.go:22), [flow hook](/Users/abc/Documents/overkill/internal/agent/agent.go:687), [daemon store](/Users/abc/Documents/overkill/cmd/overkill/daemon.go:273), [unconsumed daemon sink constructor](/Users/abc/Documents/overkill/cmd/overkill/flow_rpc.go:50). The comments in `wiring_audit_test.go` claiming these are wired are stale; a green constructor inventory is insufficient evidence.

5. **Shell detection still has gaps.** A non-executing probe of the real scanner and bash classifier finds the reversed `rm` flag orders, reversed `dd` arguments and `curl | dash` / `curl | zsh` are not blocked by the command scanner. The latter examples and reversed `rm`/`dd` also receive `allow` from the bash classifier. This proves classification gaps, not an end-to-end sandbox escape. [Results](/Users/abc/Documents/overkill/.cache/zip-review-scanner-probe.jsonl), [patterns](/Users/abc/Documents/overkill/internal/security/scanner.go:143). No destructive command or network payload was executed.

6. **Desktop credential protection is ahead of CLI/TUI onboarding.** Desktop settings encrypt through Electron safeStorage and generate a config containing an environment reference. CLI setup can still assign a supplied key directly to `Config.Providers`, then save TOML; API `config.create` also saves provider objects. The ZIP's universal “never plaintext config” promise is therefore not met. [Desktop storage](/Users/abc/Documents/overkill/desktop/src/settings.cjs:74), [CLI key assignment](/Users/abc/Documents/overkill/internal/config/setup.go:340), [CLI save](/Users/abc/Documents/overkill/cmd/overkill/setup.go:331), [API config create](/Users/abc/Documents/overkill/internal/api/handlers.go:568). Environment references are supported, but do not make every onboarding route use a secure store.

7. **Plan mode is not a hard read-only contract.** `/plan` selects safe autonomy and spec generation; it does not install the separately implemented readonly/Reader execution restriction. Safe approval mode can still authorize mutations, whereas the vision promises no code execution. [Slash command](/Users/abc/Documents/overkill/internal/agent/slash_commands.go:124), [Reader enforcement regression](/Users/abc/Documents/overkill/internal/agent/reader_mode_effects_test.go:1).

8. **“Sit and think” is partial.** `/think`, decomposition and queue progress exist on Run. Its loop calls `runAdmitted` on the same agent/history for each item, without using `ItemContext` to load and isolate each item's actual files. The reflection/decomposition hook is absent from Stream. Consequently the “each call sees only relevant files” contract is not satisfied. [Run hook](/Users/abc/Documents/overkill/internal/agent/agent.go:1322), [item loop](/Users/abc/Documents/overkill/internal/agent/agent.go:2778), [unused context mapper](/Users/abc/Documents/overkill/internal/agent/sequential.go:377).

9. **Situational awareness uses an invented inventory.** The heuristic reflection implementation is useful scaffolding, but its availability check examines a static affordance map containing `edge_tts`, rather than the actual enabled registry whose TTS tool is `tts.speak`. [Inventory](/Users/abc/Documents/overkill/internal/agent/reflect_before.go:40), [user model hook](/Users/abc/Documents/overkill/internal/agent/agent.go:2765), [real TTS tool](/Users/abc/Documents/overkill/internal/tools/tts/tts.go:1). 10. **Cost reporting lacks the promised savings proof.** Router/cost/budget infrastructure and durable coordination accounting exist, but no `overkill context report` with measured compression/cache savings and a documented dollar counterfactual was found. SmartRouter is concretely wired for subagent selection; this is insufficient evidence for automatic cheapest-capable routing of every parent turn. [Subagent routing](/Users/abc/Documents/overkill/cmd/overkill/subagent_setup.go:38), [LCM accounting](/Users/abc/Documents/overkill/internal/compaction/lcm.go:99). The ZIP's 60–70% savings and permanent improvement claims need repeatable measurements, not component counts.
