# Overkill versus 20 agent harnesses: feature-by-feature

Source comparison with a later implementation checkpoint, October 23, 2026, America/Los_Angeles. Original Overkill baseline: `1839271dfeec89773428e1ebc5c1627ffc1a9a8a`.

The useful conclusion is that Overkill already has much of the durable backend foundation, but its agent execution, terminal, browser, extension and review workflows are uneven. More feature names will not close those gaps. Existing skill evolution, item context, checkpoint/resume and local peer work should not be rebuilt from stale missing-feature lists.

This compares **105 separately scoped contracts** with 20 reviewed products/frameworks. The detailed crosswalk contains **902 overlapping reference-pattern pairings**, not 902 unique vendor features or proof of complete compatibility. Core, extension, experimental, hosted and proprietary boundaries are retained. An entry in the crosswalk identifies a useful comparison; it does not certify that every upstream host ships that feature by default. Framework contracts and optional extensions are not stock app behavior.

Research refresh: upstream HEAD `60ba4afb1d7624b0f54e2efc653e36f6170cfb29` was fetched and its delta reviewed. Omnigent is now the 20th entry, pinned at `caa0441fddfcfe407e38be04b55850a128be2dd2`. This update adds nine explicit subscription/continuity contracts (F97–F105), rather than hiding the proposed edge under generic model routing. **Native subscription workers and mixed-harness teams are the competitive minimum, not Overkill exclusivity.** F52 moves from P2 to P0.

| Question | Source-audited finding |
|---|---|
| Can it use existing subscriptions? | Yes: CLI-owned subscription provider entries and real Claude/Codex native workers. Account allowance/billing eligibility was not live-qualified. |
| Can it choose different harnesses? | Yes at launch/spawn; in-session turn routing retains the harness. |
| Does `route_with_fallback` prove subscription failover? | No. It replaces the external routing service with a local routing judge. The isolated probe invoked two routers and zero workers. |
| What happens to an exhausted native worker? | Failure is forwarded/classified and exposed to the UI/parent; rate-limit Retry continues that session. Some exhausted-credit 429 messages share the ordinary rate-limit code. |
| Can a user or agent continue elsewhere? | Explicit cross-agent/harness forks exist. A supervisor can receive a failed worker result and replan through its tools. Neither is a deterministic quota-triggered handoff guarantee. |
| Is complete subscription failover implemented? | No explicit account/reset-aware, safe cross-harness worker or supervisor handoff controller was found in the inspected production paths. This is bounded negative evidence, not a claim of global absence. |

The stronger Overkill target is a durable controller that distinguishes throttling, exhausted allowance, billing, expired auth and network failure; selects an eligible authorized route; stops/fences the previous writer; passes task/diff/test/question evidence; validates the replacement result; and reports the paying route without silently enabling paid fallback. The controller must still function when the supervising model is quota-limited. Unknown allowance and uncertain external effects stay visibly unknown.

## How to read the states

| State | Meaning |
|---|---|
| **Have** | The named bounded workflow is wired. Its explicit scope and evidence limits still apply; this is not whole-product parity. |
| **Partial** | A usable primitive or path exists, but the matching lifecycle, integration, client coverage or acceptance is incomplete. |
| **Unwired** | Relevant implementation exists, but the required production caller/activation is absent. |
| **Missing** | No matching implementation was identified in the bounded production inspection. Custom external composition is not ruled out. |
| **Unverified** | Insufficient evidence to establish the behavior or quality comparison. This is not absence. |

The counts below describe our selected Overkill contracts, not a vendor ranking: **31 Have, 41 Partial, 3 Unwired, 29 Missing, 1 Unverified**. Two products can receive different matching assessments for the same primitive: a working five-component canvas does not equal a general artifact platform, and reviewed skill generation does not equal unattended self-improvement.

The source-audit pass changed no product code, dependencies, deployment or release; the later implementation checkpoint is recorded separately above. The original 19-entry pass was static; the Omnigent addendum also executed seven isolated classifier cases and one router-service fallback probe, with no app, upstream pytest suite or live subscription account. Source and test/document references were read; previous executed evidence is identified separately. A test existing in the repository is not a claim that it was executed today.

1. **Plugin execution:** the normal extension backend says its plugin process manager is not connected (F29). Discovery/listing is not active execution.
2. **Main-agent routing:** production search finds `SetModelRouter` only at its definition, despite a model-selection branch (F43). The separate subagent SmartRouter is wired.
3. **Cross-provider failover:** production search finds `NewFailoverChain` only at its constructor definition (F93). Ordinary provider retry/backoff exists and is rated separately.

**Correction to old research:** external owner-controlled file hooks are loaded via `hooks.NewRegistryFromDir` in shared runtime construction and gateway commands. They are not currently unwired. Their missing piece is a richer policy/transform return protocol.
