# Private PostgreSQL identity verification

The private database manager authenticates its loopback connection using the generated cluster credential. It compares the configured data directory and port with SQL `current_setting` values, then reads the connected server's own `postmaster.pid` through `pg_read_file('postmaster.pid',0,8192)`. Its PID, data directory, PID-file start value, and port must exactly match the locally recorded identity. The same strict parser handles disk and SQL reads. Disk reads are bounded to 8193 bytes so oversized files can be rejected; the SQL read is bounded to 8192 bytes. No timestamp tolerance is used.

This fixes an invalid comparison between the PID-file timestamp and `floor(extract(epoch FROM pg_postmaster_start_time()))`. PostgreSQL 17.11 writes `MyStartTime` into the PID file ([miscinit.c, lines 1349–1353](https://github.com/postgres/postgres/blob/REL_17_11/src/backend/utils/init/miscinit.c#L1349-L1353)). Its process initialization assigns that value early, while later startup assigns the distinct `PgStartTime` value ([postmaster.c, process initialization](https://github.com/postgres/postgres/blob/REL_17_11/src/backend/postmaster/postmaster.c#L1900-L1908), [later startup](https://github.com/postgres/postgres/blob/REL_17_11/src/backend/postmaster/postmaster.c#L1262-L1265)). The SQL function returns `PgStartTime` ([timestamp.c, lines 1544–1547](https://github.com/postgres/postgres/blob/REL_17_11/src/backend/utils/adt/timestamp.c#L1544-L1547)). These readings can cross a second boundary; equality is not a valid ownership invariant. The new check compares the same PID-file identity through both authenticated SQL and the filesystem.

The observed desktop restart failure logged server startup at `13:53:37.999` and readiness at `13:53:38.003`, followed by a readiness timeout. That timing is consistent with this defect, but the old error path discarded the verifier failure and did not capture the two compared values. Attribution of that exact failed run to the timestamp mismatch remains an inference. The source-level defect itself is directly established by the upstream implementation.

Readiness timeout errors now preserve the last failed verification stage, while redacting the private password. Query strings contain no credential. Orphan recovery continues to require the recorded PID/start/port and authenticated server identity before controlled shutdown; verification failure preserves the process and data.

Native PostgreSQL tests cover successful authentication; altered expected PID, start, port, and directory; strict bounded parsing; last-check timeout diagnostics; persistent restart; lifetime cancellation; and authenticated orphan recovery. They do not replace installed application testing.
