## Updater integrity repair

The installer reinspection also confirmed a separate unsafe CLI updater. Before repair, a controlled HTTP404 for checksums returned an empty string that meant “skip verification,” and an arbitrary sole release asset was selected as fallback. `.cache/updater-security-before.log` records both failures.

`update_integrity.go` now requires an exact unique supported-platform basename and a mandatory strict checksums.txt match before replacement. The API response is bounded to 1 MiB, manifest to 64 KiB and binary to 512 MiB plus its exact declared release size. Manifest entries require valid 64-digit SHA256 values and exact non-path basenames; missing/unlisted/duplicate/malformed entries or download/hash errors fail closed. Valid standard text/binary checksum lines and uppercase hash digits remain supported.

The existing owner/name repository option/environment is validated and used only with the fixed GitHub releases API. Initial asset URLs must match that repository, selected tag and exact basename on HTTPS GitHub. Redirects are bounded to GitHub's release asset CDN hosts, HTTPS only; API redirects are rejected, and asset redirects never forward Authorization or Cookie. No attacker-controlled URL configuration, insecure TLS option or test transport is exposed in production.

A unique sibling tempfile receives verified bytes. A durable backup copy precedes one atomic rename over the live executable, so final publication failure leaves the original at its live path. Validation/download failures preserve both the live file and existing retained backup. Windows receives a verified manual replacement file without modifying the locked live executable. Both CLI update and rollback reject a backend under `*.app/Contents/Resources/bin` with the explicit DMG installation message, preserving the desktop bundle's signature/resource hashes.

`.cache/updater-security-focused-race.log` records production-helper acceptance with actual controlled HTTP, all five exact platform targets, mandatory integrity error preservation, allowed/rejected redirects, API authentication/no redirect leak, bounded/truncated/cancelled responses, verified Windows staging, actual downloaded native executable execution, forced final-rename failure while the original live path remains present, owned rollback and desktop bundle mutation rejection. `.cache/updater-security-command-race.log` records the passing full command package race gate; `.cache/updater-security-windows-build.log` records a successful Windows/amd64 cross-build, without claiming native Windows execution. These tests never mutate the test runner, user's installed binary, Keychain or an installed application.
