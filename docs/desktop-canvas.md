# Canvas in the desktop workspace

The desktop window now displays the same durable canvas documents as the browser workspace. Select a chat, open **Canvas**, select its surface and use **Save PNG**. Export uses bundled Electron, so it does not require an additional Chrome executable. Empty/loading/error states, current revision and stale-export errors are shown in the panel.

The session-bound `canvas` model tool can read, create, update and reset the current chat's canvas. Its schema accepts only `{action,jsonl?}`. The application fixes the persisted session identity; model input cannot choose another session, workspace, file, URL, script or HTML document. Apply/reset mutations follow existing privilege, scope and required-contract guards. Reader mode permits a valid state read and rejects mutations. This does not make a model's drawing claim trusted: only accepted backend mutations change the canvas.

The explicit custom catalog remains **overkill.canvas.v1**: Text, Heading, Column, Row and Divider, with safe scalar data bindings. It is not full A2UI or OpenClaw widget compatibility. See [the canvas contract](canvas.md) for event examples, replacement semantics, database/revision limits and supported content.

Native export rereads committed state and requires the selected displayed revision. A newer revision causes a visible refresh/retry error rather than exporting a different drawing under the old label. A short-lived hidden sandboxed window renders frozen data through exact copies of the browser renderer/CSS, with navigation, popups, permissions and network denied. It captures actual pixels, explicitly normalizes backing-scale output to **960×640**, and closes the owned capture window. The native Save dialog chooses the path; the renderer cannot supply an arbitrary filesystem path. Publication stages a private file beside the destination and renames it atomically; cancellation before publication preserves an existing destination. One export can run at a time, with a capture timeout and app/backend lifetime checks.

Only named renderer IPC methods are exposed: `canvasState` and `saveCanvasSnapshot`. Fixed authenticated backend RPC methods are `canvas.state`, `canvas.apply` and `canvas.reset`; no generic renderer RPC bridge was added. Reads inspect committed state without waiting for a model turn. Application mutations use ordinary session admission; the model's already-admitted tool calls use the bound store directly to avoid recursive admission.

Changing chats aborts/ignores stale state replies and prevents old export completion from updating the new chat. The panel refreshes only while open and bound to an active chat. Store reconstruction and actual app/database relaunch preserve accepted canvas state. Canvas data is part of the session store and follows its deletion lifecycle; separate durable ACP task receipts have their own retention contract.

The canonical browser renderer assets are copied deterministically by desktop preparation and checked byte-for-byte before packaging. Do not edit generated `desktop/src/canvas.js` or `canvas.css` independently. The dedicated native/API tests inspect the real shared-store path, bindings, PNG bytes/dimensions/content changes, stale revisions/replies, two-chat isolation, cancellation, concurrent export handling, capture-window cleanup and relaunch. A controlled provider exercises the actual session-bound tool; no paid provider is implied.

Implementation and exact acceptance receipts are recorded in [the integration record](desktop-canvas-plan.md). Root inspected `.cache/desktop-canvas-native.png`. The existing development DMG remains frozen and excludes these source changes; installed-app, stable signing, minimum-OS and cross-platform acceptance remain separate work.
