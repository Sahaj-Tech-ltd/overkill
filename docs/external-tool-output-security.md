# External tool results and LSP path containment

The LSP client resolves the workspace and file ancestors through symlinks before sending file queries. Missing files under existing safe ancestors remain supported. Dangling links, links escaping the workspace, and a client without a workspace root fail closed. Definition, reference, document-symbol, and workspace-symbol results are checked as local file URIs and must also resolve inside the workspace. A response containing an escaping location is rejected as a whole.

The client sends the resolved canonical input path. This closes the simple symlink escape in the previous lexical check. It is not an operating-system sandbox: a configured language server runs executable code with the app user's permissions. Concurrent filesystem replacement can still race a server's later file access. Argument sanitization cannot turn an untrusted executable into a trusted server. Configure language-server commands only from trusted configuration. This change deliberately rejects external dependency locations too; broader read roots need an explicit future policy.

Both synchronous and streaming agent execution pass model-history tool results through `Agent.appendToolResultMessage`. The common context boundary annotates all `lsp_` and actual `mcp:<server>:<tool>` results, including errors, as untrusted external data. The annotation is a JSON envelope whose `data` string retains the model-context result after existing compression/truncation. Executed tool results, hook results, receipts and tool events retain their original payloads. External context has a further 128 KiB data bound and invalid UTF-8 is repaired before JSON encoding; tool source labels are bounded too.

The existing prompt-injection heuristic scans bounded data and decoded JSON strings, so Unicode JSON escapes do not simply hide instructions. A suspected-injection flag is advisory. Every result carries the untrusted annotation even when no attack is detected. This does not prove that a model will ignore an attack, detect all encodings, preserve the annotation through every future compactor, or isolate arbitrary output from other tool families. The model still needs independently authorized tool actions and normal execution guards.
