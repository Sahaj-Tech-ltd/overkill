## Historical source proof

The historical cost date-expression index really fails with SQLSTATE 42P17 on this PostgreSQL server. This source-bound baseline plus explicitly supported predecessor fixtures is the old-schema evidence; no collection of every archived database dump is claimed.

## Retention defect and repair

The old `max*5` list window could contain only children and hide all eligible roots; it also failed to consider roots beyond that window. The real pre-fix reproduction with 12 roots/20 old children deleted zero instead of ten (`.cache/validate01-retention-before.log`). PostgreSQL now selects initial top-level candidates in one repeatable-read transaction and processes IDs in batches of 128 through the existing family-preserving delete. Failure rolls everything back. Generic stores scan bounded 64-session pages into a private temporary ID/version spool before deleting; repeated/nonmonotonic pages fail visibly. This avoids deleting while offset paging and avoids multiplying an arbitrary cap.

The cap applies to initially top-level sessions. Existing policy promotes children of a deleted parent; those original children are preserved. Concurrent new roots belong to a later pass. Generic Store has no compare-and-swap transaction: changed candidates are skipped on a best-effort version recheck, never replaced with newer deletions, and concurrent writes can require another pass. PostgreSQL concurrent writers can produce an explicit serialization error with rollback. No production call currently invokes `EnforceMax`; acceptance covers the executed retention helper and does not claim automatic retention is enabled.

## Reproduction and limits

Set `PG_TEST_URL` to an isolated-test-capable PostgreSQL database and `OVERKILL_REQUIRE_TEST_DB=1`, then run:

```sh
.cache/toolchains/go/bin/go test -race -json -p 4 \
  ./internal/db ./internal/dbschema ./internal/session ./internal/agent \
  ./internal/cost ./internal/learning ./internal/cron ./internal/daemon \
  ./internal/memory ./internal/gateway -count=1 -timeout=3m
.cache/toolchains/go/bin/go vet ./internal/db ./internal/dbschema ./internal/session \
  ./internal/agent ./internal/cost ./internal/learning ./internal/cron \
  ./internal/daemon ./internal/memory ./internal/gateway
python3 scripts/build-historical-schema-fixture.py --check
```

Vet passed (`.cache/validate01-vet.log`). A test-only mutex-copy warning was corrected by constructing a fresh fixture Session; the corrected repeated-page regression passes with race detection (`.cache/validate01-retention-vet-followup.jsonl`). The final three-check baseline follow-up also passes after strengthening explicit historical folder/timestamp assertions (`.cache/validate01-baseline-final.jsonl`). Production files were unchanged by these follow-ups.

This proves the named assertions on one configured PostgreSQL runtime. Constructor reconstruction over durable rows is not OS-process kill/power-loss, backup/restore or major-version acceptance. Separate store migrations remain separate transactions; older binaries/manual DDL need not honor advisory locks. Arbitrary same-name objects, all permission/extension states, pgvector/real semantic models, live messaging/provider protocols and cross-platform release installation remain separate claims. See the earlier [migration matrix](postgres-migration-matrix.md) and owner safety documents for the detailed boundaries; this report supersedes only its historical-baseline evidence gap for the original enumerated VALIDATE-01 criterion.
